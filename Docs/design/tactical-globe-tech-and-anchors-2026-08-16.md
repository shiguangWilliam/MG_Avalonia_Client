# Tactical 地球仪：技术栈、卡顿评估与导航锚点方案

> 日期：2026-08-16  
> 范围：`ClientAvalonia` Tactical 战役地球（`TacticalGlobeView` / `DxCampaignGlobeHost` / `GlobeTextureBaker`）  
> 性质：实现现状报告 + 卡顿根因评估 + 后续需求（选战役旋转/放大、可见导航锚点）方案，**本文件不落地代码**

---

## 1. 当前技术栈

### 1.1 运行时与渲染

| 层 | 技术 | 说明 |
|---|---|---|
| UI 框架 | Avalonia 11（.NET 8） | 桌面客户端，非 Unity / 非 WebGL |
| 地球控件 | 自定义 `Control`：`TacticalGlobeView` | 自绘，无 Skia 自定义着色器、无 GPU mesh |
| 位图 | `WriteableBitmap` + `ILockedFramebuffer`（unsafe） | 球面贴图每姿态栅格化到 320×320 |
| 矢量叠加 | `StreamGeometry` / `EllipseGeometry` / `FormattedText` | 海岸线描边、经纬网、任务标记、大气环 |
| 定时器 | `DispatcherTimer`（~33ms，Background 优先级） | 自转 / 惯性 / `InvalidateVisual` |
| 交互 | Pointer 拖拽 → 改 `Yaw`/`Pitch` | 惯性衰减 + 可选自动慢旋 |

**结论：CPU 软件光栅路径**，所有重计算跑在 UI 线程；不是独立 3D 引擎。

### 1.2 几何与投影

- **模型**：单位球 + 透视相机（`FocalFactor = 3.4`）
- **姿态**：`Yaw` / `Pitch`（度）；渲染时量化步长 `PoseQuantizationDegrees = 0.6`
- **正向**：`lat/lon →` 旋转 → 透视投影（任务点、矢量海岸线、经纬网共用）
- **反向**（贴图采样）：屏幕像素 → 射线-球求交 → `atan2/asin` → 等距圆柱 UV

### 1.3 贴图管线

| 组件 | 职责 |
|---|---|
| `GlmAssets.WorldMap` | 嵌入资源 `Assets/Glm/world_map.png`（avares） |
| `GlobeTextureBaker` | 优先把 AI 等距圆柱图拷成 `uint[]` BGRA；缺失则程序化栅格化 `ContinentOutlines` |
| `ContinentOutlines` | 低精度大陆多边形（矢量叠加层仍在用） |
| Tactical 预热 | `DxThemeManager.PreloadTacticalAssets` 后台 `WarmUp` |

当前贴图典型尺寸约 **1728×850**（裁水印后）；球盘缓存固定 **320×320**。

### 1.4 战役数据绑定

| 组件 | 职责 |
|---|---|
| `Battle.ini` → `MissionEntry.GlobeLatitude/Longitude` | 可选真实经纬度 |
| `MissionCatalogLoader` / `CatalogListItemViewModel` | 传到列表 VM |
| `DxCampaignGlobeHost` | 从 `lbCampaignList` 建 `GlobeNode[]`；有坐标用真实值，否则 **FNV 哈希散布** |
| 双向同步 | 列表选中 ↔ `SelectedNodeIndex`；地球点击回写列表 |

### 1.5 视觉分层（每帧 `Render`）

1. 贴图球盘 `DrawImage`（有缓存时可不重建位图）  
2. 矢量海岸线（半球裁剪 + 投影）  
3. 经纬网（12 经线 × 6 纬线折线）  
4. 边缘 / 大气环  
5. 任务标记（方标 + 选中括号 + 标签文字）

## 2. 卡顿评估（人工评测「较严重卡顿」）

### 2.1 热路径开销估算

**球面位图重建**（`RenderSphereBitmap`，姿态变化超过 0.6° 时）：

- 分辨率：`320 × 320 ≈ 1.0×10⁵` 像素  
- 每像素典型成本：圆盘剔除 + 二次方程求根（`sqrt`）+ 姿态逆变换 + `atan2` + `asin` + 贴图寻址 + N·L  
- 量级：单次重建约 **数 ms～十余 ms**（机器相关）；拖拽时几乎每帧触发一次重建  

**自动旋转**：`2.4°/s ÷ 0.6° ≈ 4 次/秒` 重建——空闲时也可能周期性尖刺。

**即使位图命中缓存**，`InvalidateVisual` 仍会：

- 重投全部矢量海岸线（多边形半球裁剪）  
- 重绘经纬网（每条弧数十段）  
- 重绘全部节点标记  

定时器 **~30 Hz** 在自转开启时持续 `InvalidateVisual`。

### 2.2 根因排序（按嫌疑）

| 优先级 | 根因 | 症状特征 |
|---|---|---|
| **P0** | UI 线程软件射线追踪栅格化 320² | 拖拽时卡顿最明显；CPU 单核冲高 |
| **P1** | 姿态量化过细（0.6°）→ 拖拽重建过频 | 拖一点就重建 |
| **P2** | 自转 + 33ms 定时器持续脏矩形 | 空闲也「一顿一顿」 |
| **P3** | 每帧矢量海岸线 + 密经纬网 | 贴图已有大陆时仍双份地理成本 |
| **P4** | AI 贴图 1728 宽，每像素 UV 寻址跨度大（次要） | 对重建成本贡献小于求交本身 |
| **P5** | 战役窗加宽（~1240×660）+ 双栏浮动 + 星域底图 | 整体合成压力，非地球独有 |

### 2.3 建议的缓解路线（仍不落地，仅评估）

**短平快（预计 0.5–1.5 人日）**

1. 拖拽中降采样：`SphereRenderSize` 160，松手再 320  
2. 量化放宽：拖拽 2°、空闲 1°；自转可降到 1°/s 或默认关  
3. Tactical 贴图模式下 **关掉矢量大陆填充/描边**（贴图已表达陆地）  
4. 经纬网减半或仅选中时显示  

**中期（2–4 人日）**

5. 球面栅格化挪到线程池，完成后再回 UI 交换 `WriteableBitmap`（注意 Avalonia 位图线程亲和）  
6. 预烘焙若干 yaw 切片做插值（内存换 CPU）  

**长期（若要城市级放大）**

7. 放弃每帧 CPU 射线球，改为 Avalonia 可组合的简化方案（见 §3）或引入轻量 GPU 路径  

**验收指标建议**：拖拽时 UI 线程单帧球面重建 &lt; 4ms（中端机）；空闲自转无肉眼可感尖刺。

## 3. 选战役 → 旋转 / 放大 / 城市细节（原方案，补充）

> 此前约定：写方案不落地。此处固化并与锚点需求合并。

### 3.1 目标体验

1. 选中战役列表项 → 地球平滑旋转，使该任务经纬度进入视口中心  
2. 可选放大（剧院级）  
3. 「城市细节」为独立 LOD，**不能**指望当前 1728 宽全球贴图放大看清街区  

### 3.2 LOD 划分

| 级别 | 名称 | 内容 | 数据 |
|---|---|---|---|
| L0 | 全球 | 现有球 + 贴图 + 锚点 | `world_map` + `GlobeLat/Lon` |
| L1 | 剧院 | 相机推进（改 `RadiusFactor`/`Focal` 或等效缩放） | 同贴图，清晰度有限 |
| L2 | 城市/任务 | 任务专用细节板或插画淡入 | 每任务一张图 / 短文案 HUD，**非**全球贴图像素放大 |

### 3.3 推荐架构（混合，性价比最高）

```
选中战役
  → 暂停自转
  → 插值 Yaw/Pitch 对准 (lat,lon)     [L0→瞄准]
  → 可选缩放到 L1                      [剧院]
  → 若需城市细节：淡入 L2 任务板       [不硬放大全球 UV]
```

**不推荐**：全球贴图金字塔瓦片（Mapbox 级）——与启动器体量、Avalonia CPU 路径不匹配。

### 3.4 工作量粗估

| 项 | 人日 | 备注 |
|---|---|---|
| 选中 → 姿态插值对准 | 0.5–1 | 已有坐标与 `Yaw/Pitch` |
| L1 缩放动画 + 松手恢复 | 0.5–1 | |
| L2 任务细节板（INI/资源约定） | 1–2 | 美术另计 |
| 卡顿缓解（§2.3 短平快） | 0.5–1.5 | **建议与旋转对准同迭代** |
| **合计（无 GPU 重做）** | **约 3–5 人日** | 不含全任务 L2 美术 |

若坚持「无缝放大到真实城市卫星图」：另加瓦片/GPU，**≥10 人日** 量级，不建议 P0。

## 4. 追加需求：视图导航坐标锚点（Visible Anchors）

### 4.1 需求陈述

> 每一个战役的坐标都要在地图上呈现为**可见锚点**，用于视图导航与空间认知。

即：不只是「选中才高亮」，而是 **列表中每个有地理意义的任务在球面上常驻可见标记**。

### 4.2 与现状差距

| 能力 | 现状 | 目标 |
|---|---|---|
| 节点数据 | 已有：`GlobeNode` 列表，来自列表项 | 保持 |
| 真实坐标 | `GlobeLatitude/Longitude`，缺则哈希 | **P0：尽量配齐 INI 真实坐标**；哈希仅作开发回退 |
| 绘制 | 小方标 + 中心点；背面半透明 | 加强为「导航锚」视觉语言 |
| 未选中可见性 | 有，但偏弱、易被贴图淹没 | **全部前线锚点可读** |
| 选中 | 括号 + 标签 | 保留并增强（脉冲/引线） |
| 列表↔球 | 已双向 | 锚点点击 = 导航到该战役 |

### 4.3 锚点设计规范（建议）

**视觉（对齐 Tactical `#2EE6C5`）**

- 默认：青色菱形 / 方标 + 1px 外环，尺寸随深度略缩  
- 锁定（不可用）：muted 灰，空心  
- 选中：反色强调 + 角括号 + 短标签（任务名截断）  
- 背面半球：降低透明度或不绘制标签（避免穿透干扰）  

**行为**

- 常驻显示当前阵营/列表过滤后的全部任务锚点  
- Hover：放大 + 名称 tooltip  
- Click：选中列表项；若已实现姿态对准，则同时触发旋转  

**数据**

- INI：`GlobeLatitude` / `GlobeLongitude` 作为正式导航坐标  
- 校验：纬度 [-90,90]，经度 [-180,180]；缺省打日志并用哈希（调试模式可显示「估算」标记）  

### 4.4 实现增量（相对现状）

| 项 | 人日 | 说明 |
|---|---|---|
| 锚点样式强化（未选中也清晰） | 0.5 | 纯 `TacticalGlobeView` 绘制 |
| 过滤规则（仅当前 side / 列表可见项） | 0.5 | `DxCampaignGlobeHost` |
| Battle.ini 批量补坐标 | 1–2 | 策划/关卡；程序只提供校验工具 |
| 与「选中旋转对准」联动 | 含在 §3.4 | |

**合计锚点专项：约 1–1.5 人日（不含配坐标）**。

### 4.5 验收清单

- [ ] 打开 Tactical 战役：当前列表每个任务在地球上有可见锚点  
- [ ] 无 `GlobeLat/Lon` 的任务位置与设定一致（抽样对照）  
- [ ] 缺坐标任务有明确回退策略且不崩溃  
- [ ] 点击锚点 ↔ 列表选中一致  
- [ ] 拖拽/自转时锚点与贴图大陆套合，无明显错位  
- [ ] 卡顿缓解项落地后，拖拽主观可接受

## 5. 建议迭代顺序

1. **卡顿短平快**（§2.3）——否则旋转动画与多锚点会放大卡顿  
2. **可见导航锚点**（§4）——数据与交互已具备，主要是表现与坐标完备  
3. **选中旋转对准**（§3 L0）  
4. **L1 剧院缩放**（可选）  
5. **L2 城市细节板**（按任务美术排期）

## 7. 一句话结论

当前地球是 **Avalonia UI 线程上的 CPU 透视球 + 等距圆柱贴图采样**，卡顿主因是 **拖拽时频繁的 320² 软件射线栅格化**；导航锚点需求在数据链路上已基本打通，缺的是 **更强的常驻锚点表现 + 真实坐标完备 + 选中对准动画**，城市细节应走 **L2 任务板** 而非放大全球贴图。
